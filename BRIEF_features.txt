WHAT features.py MUST DO

Command line: `python features.py select --seed 0` (argparse, subcommand-style like the existing src/activations.py which uses `ap.add_argument("stage", choices=[...])` - match that style). Fully deterministic given the seed.

Step 1. Streaming statistics pass.
Iterate over data/acts.f16 in chunks of at most 4096 rows. For each chunk: move to GPU as float32, run sae.encode under torch.no_grad(). Accumulate per feature (all 24576):
  - n_active: count of rows where activation > 0
  - sum_active: sum of activations over rows where activation > 0
  - a running top-K of the largest activations together with the token id that produced them, K = 256.
Implement the running top-K by concatenating the current running values/tokens with the chunk's per-feature top-K and re-applying topk along the token axis, so memory stays O(K * 24576). Keep the running buffers on GPU as float32 values and int64 token ids. Free per-chunk tensors so peak memory stays under the 4 GB budget; reduce the chunk size if needed and say so in a comment. Show progress with tqdm.
Derived: freq[f] = n_active[f] / N, mean_act[f] = sum_active[f] / max(n_active[f], 1).

Step 2. Usable-feature filter.
Keep features with 1e-4 <= freq <= 5e-2. Call this the surviving set.

Step 3. Lexical coherence.
For each surviving feature, take its top-256 (activation, token id) pairs. Group the activations by distinct token id and sum them. coherence[f] = (sum of the 10 largest per-token-id activation masses) / (total activation mass of the 256 entries). Range (0, 1]; higher means the feature fires on a small lexical set.

Step 4. Geometry, computed from ActStats (float32 on GPU, or float64 on CPU if that is easier - state which).
For each surviving feature, with v = sae.W_dec[f], v_hat = v / ||v||, Sigma = stats.cov:
  - dec_norm[f] = ||v||
  - var_along[f] = v_hat^T Sigma v_hat
  - kappa_tilt[f] = || Sigma v_hat - (v_hat^T Sigma v_hat) * v_hat || / (v_hat^T Sigma v_hat)
    (that is, the norm of the component of Sigma v_hat orthogonal to v_hat, divided by var_along)
Do this as batched matrix algebra over the surviving features, not a Python loop over 24576 items.

Step 5. Selection (seeded, reproducible).
Take the 200 surviving features with the highest coherence as the candidate pool. Shuffle the pool with the given seed. Walk the shuffled pool and greedily accept a feature only if the absolute cosine similarity between its v_hat and the v_hat of every already-accepted feature is below 0.3. Accept the first 12 as TEST and the next 6 as DEV. If the pool is exhausted before 18 are accepted, raise a clear error naming how many were found.

Step 6. FIT set.
FIT = all feature indices in [0, 24576) that are (a) not in TEST or DEV, and (b) have absolute cosine similarity below 0.3 against every TEST and DEV direction. Save as a sorted int32 array to data/splits.npz together with the TEST and DEV index arrays (keys: "test", "dev", "fit"). Compute the cosine matrix in chunks to respect the memory budget.

Step 7. Keyword sets and human-readable token lists.
Use load_model().tokenizer (or model.to_string) to decode token ids. For each TEST and DEV feature:
  - top_tokens: the 15 distinct token strings with the largest summed activation mass in the top-256, in descending order, with leading spaces preserved and shown explicitly, e.g. represent " Paris" as "_Paris" using a single leading underscore for a leading space so that YAML stays readable.
  - keywords: take distinct token strings in descending mass order, accumulate until the cumulative mass reaches 80% of the total, then clean the list: strip whitespace, lowercase, drop entries shorter than 3 characters, drop entries that are entirely punctuation or entirely digits, deduplicate while preserving order. Keywords are stored without the underscore marker.
