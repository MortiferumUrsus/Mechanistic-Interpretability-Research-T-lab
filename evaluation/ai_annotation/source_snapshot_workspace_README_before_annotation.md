## Как устроен каждый трек

- `PLAN.md` — предрегистрация: требования задания, гипотезы с числовыми предсказаниями, метрики,
  порядок работ. Коммитится **до** запусков, чтобы предсказания были видны по git-истории.
- `REPORT.md` и `report.html` — отчёт; HTML собирается общим рендерером
  [`tools/make_html.py`](tools/make_html.py), фигуры вложены как data URI. Рендереру нужны `markdown` и
  `pygments`: `python -m pip install markdown pygments`, затем `python ../tools/make_html.py REPORT.md
  --out report.html` из папки трека.
- `src/` — код, `results/` — сырые csv и графики, `kaggle/` — самодостаточные ноутбуки, где нужны.
- `reviews/` — внешние ревью плана, где они собирались. Разбирались построчно; принятые правки
  внесены в план и отчёт с обоснованием.

## Что изменилось после внешнего аудита

Аудит каждого трека против его же файлов результатов нашёл утверждения, которые артефактами не
подтверждались. Три находки стоит знать до чтения отчётов, потому что они меняют выводы:

1. **Трек 1.** Числа второго раунда были посчитаны по генерациям, испорченным багом кэша направлений, а
   «репликация на невиданных признаках» шла на обучающих. После пересчёта и перепрогона выигрыш оказался
   больше заявленного, а прежний вывод «вклад обучения ограничен текстовой осью» снят: он опирался на
   контроль, бравший одну случайную ось на все признаки.
2. **Трек 2.** `LeRobotDataset` молча терял данные: метаданные датасета ссылаются на 69 файловых индексов
   при 377 физических шардах. Для целевых задач загружалось ноль строк, поэтому дообучение «на 25
   демонстрациях» шло без единой из них. Это и есть причина нулевого success во всех прежних роллаутах.
3. **Трек 3.** Метрика, на которой держался причинный вывод, считалась в коде, но не попадала в лог.
   Вывод снимался с величины, равной между арками по построению.

## Что нужно от владельца машины

1. **Опубликовать чекпойнт трека 1 на Hugging Face.** Условие требует этого прямо, и без этого сдача
   трека 1 неполна. Веса, карточка модели и скрипт лежат в `01-mech-interp/artifacts/`; сначала стоит
   посмотреть, что уйдёт, флагом `--dry-run`. Это внешнее действие под вашей учётной записью, поэтому
   автоматически не выполняется:

   ```bash
   huggingface-cli login && python 01-mech-interp/artifacts/push_to_hf.py --repo <user>/gpt2-small-steering-direction-correction
   ```

2. **Завести GitHub-remote для всех четырёх репозиториев.** Сейчас remote нет ни у одного, и ни в одном
   отчёте нет ссылки, по которой проверяющий нашёл бы код. Репозиторий требуют все четыре задания.

3. *(Снято двадцатого августа.)* Пункт «досчитать трек 2» закрыт решением, а не компьютом: квота ушла
   треку 3 по прямому приоритету владельца, отсутствие seen-претрена раскрыто в отчёте трека 2 первой
   секцией, а межсидовый разброс — главный вывод трека — добит прямым измерением (вторая арка той же
   рецептуры, ночь на двадцать первое августа).

WSL **не нужен**; LIBERO работает локально под Windows (`egl_probe` — не несущая зависимость: robosuite
выставляет EGL всюду, кроме Darwin, а под Windows его не существует и mujoco рендерит через WGL) — все
роллауты трека 2 сняты локально. Kaggle **используется и автоматизирован**: токены нового формата
(`KGAT_…`) работают с Kaggle CLI 2.x через `KAGGLE_API_TOKEN`, прогоны трека 3 пушатся посессионными
слайсами (`03-open-ended-learning/kaggle/push_session.py`, очередь — `run_waves.sh`), два GPU-кернела
параллельно, ~75 минут на полный прогон. CPU-колёса `jaxlib 0.4.30` под Windows есть — скрининговые
замеры трека 3 шли локально.
